This chapter details the architecture and algorithmic design of the proposed adaptive actuation system.

\section{System Architecture}
The system utilizes a multi-layered software and hardware stack designed to bridge high-frequency physical telemetry with a dynamic optimization engine. At the hardware layer, a modified PRO X2 Superstrike mouse streams continuous 120-level analog depth values at 1\,kHz. This bypasses typical firmware constraints that generally limit reporting to mere 4-bit precision at 65\,Hz and block reading after haptic events. The hardware communicates with the host operating system via an OS-level driver bridge that interfaces high-level prototyping environments with production-grade HID protocols. Sitting above this is a background sensor service that orchestrates and synchronizes the analog telemetry with OS events and other biometrics. Finally, a front-end orchestration client provides the user dashboard, manages recording state, and drives the downstream machine learning pipelines. \label{sec:labeling}

Raw analog signals are inherently noisy. Before any label placement, the depth telemetry is smoothed using Modified Akima (MAKIMA) interpolation. MAKIMA was specifically chosen because it preserves signal monotonicity and avoids the severe overshoots characteristic of standard cubic splines, which is critical for accurate boundary detection on a signal with sharp transitions.

\subsection{Algorithmic Bootstrapping}
To alleviate the bottleneck of manual annotation at scale, an automated heuristic pipeline pre-populates boundary candidates before human review. Detection anchors on the OS-reported digital key event to identify the approximate click window, then walks the analog signal to locate the true biomechanical boundary:

\begin{itemize}
    \item \textbf{Make Intention:} Starting from the OS make event, the algorithm walks backwards in time to find the first non-zero analog depth, or the immediately preceding local trough or valley in the depth signal. A hysteresis constraint prevents spurious detections from sensor noise near rest position.
    \item \textbf{Break Intention:} Detected at the first zero-crossing of the analog velocity (i.e., the first local peak in depth after the maximum), which typically occurs earlier than the OS-reported key release and more accurately reflects the physical start of the finger lift.
\end{itemize}

This heuristic correctly handles the vast majority of clean, well-separated clicks, providing an accurate starting point for human reviewers to correct rather than annotate from scratch.

\subsection{Iterative Human-in-the-Loop Annotation}
Annotation followed an iterative three-phase strategy designed to maximize label quality while minimizing annotation effort:

\begin{enumerate}
    \item \textbf{Algorithmic bootstrap.} The heuristic pipeline above generated initial boundary candidates for all recordings. Annotators reviewed these within a custom data visualization and labeling interface integrated directly into the front-end orchestration client. The interface renders the raw 1\,kHz analog depth signal alongside its derived velocity, and allows annotators to drag start and end boundary markers independently for the left and right button channels. Visual smoothing was applied on a per-recording basis to assist in distinguishing genuine kinetic events from micro-tremors. Annotators focused strictly on biomechanical intent, preserving deliberate presses including those not registered by the OS, while discarding involuntary micro-tremors and resting-weight drift. Approximately 50\% of the dataset was verified and corrected in this phase.

    \item \textbf{Model-assisted labeling.} Once the manually verified corpus was sufficiently large, a preliminary model was trained and used to auto-label the remainder of the dataset. Segments with a model confidence of 95\% or above were accepted automatically, covering approximately 60--80\% of the remaining unlabeled recordings.

    \item \textbf{Mixed review.} The remaining recordings --- primarily those containing clicks not registered by the OS, which the heuristic cannot anchor on --- were processed by a combination of the algorithmic heuristic and direct human annotation. A final manual review pass was conducted over all automatically labeled segments to validate quality before inclusion in the training corpus.
\end{enumerate}

The full extent and breakdown of the resulting annotated corpus is described in Section~\ref{sec:data_acquisition}.

\section{Data Preparation Pipeline}
\label{sec:data_prep}

The data preparation phase transforms raw analog and digital sensor recordings, along with the human-verified labels, into normalized arrays ready for supervised training. The pipeline ensures all three model architectures (Random Forest, Gradient Boosted Trees, and FCN) receive identical preprocessed inputs (\texttt{X\_train} and \texttt{y\_train}), standardizing the data ingestion across different algorithmic paradigms. The pipeline consists of loading, preprocessing, sequence splitting, normalization, and model-specific framing.

\subsection{Loading and Frame Extraction}
Each recording consists of sensor readings recorded at 1\,kHz and a corresponding sidecar containing manually annotated segments (start index, end index, channel, class, and source). Only manual segments are used for training; heuristically generated ("auto") segments are ignored to avoid reinforcing algorithmic bias. 

During loading, the raw frame extraction normalizes the 120-level continuous analog data to a float range $\in [0, 1]$ and casts the binary digital channels to \{0.0, 1.0\}. The segments map to three specific target labels---Make Onset, Click Hold, and Break Onset---with surrounding inactivity classified as Background. Make and Break boundaries are padded symmetrically with an onset radius of 8 frames ($\pm 8$\,ms). Both raw arrays and parsed labels are serialized efficiently with memory caching to accelerate iterative re-loading.

\subsection{Preprocessing and Signal Augmentation}
\label{sec:drift}
Preprocessing parameters dictate the specific transformations applied to the raw channels before splitting. 
The analog streams optionally undergo temporal smoothing (e.g., Gaussian, Savitzky-Golay, or moving average). Critically, derivative features are extracted to form the kinematic profiles essential for classification. A zero-phase Akima-spline derivation calculates the velocity, acceleration, and jerk to circumvent causal shift bias. Finally, a drift profile representing resting-weight baseline shifts is computed via the difference of fast and slow Exponential Moving Averages (EMA).

Decimation is applied selectively to downsample continuous channels via an 8th-order zero-phase Chebyshev IIR low-pass filter to prevent aliasing, while discrete digital signals are only strided. 

To improve computational tractability, lengthy periods of background inactivity are stripped. A rolling-window activity mask checks the mean amplitude and statistical variance against configurable thresholds to drop uninformative segments, outputting independent labeled sub-sequences while retaining predefined margins around active events. 

\subsection{Splitting, Normalization, and Sample Weighting}
The resultant sub-sequences are partitioned into train, validation, and test datasets. To ensure rigorous evaluation isolated from individual bio-signatures, the preferred k-fold splitting strategy acts at the participant level, strictly grouping segments by a \texttt{user\_id} extracted from the file metadata. A sequence allocation ensures that no participant spans both the training and evaluation splits simultaneously.

Z-score normalization is fitted exclusively on the training split to mirror live inference constraints. To prevent the prevalent background noise from anchoring the scale, baseline standard deviations for kinematic features (velocity, acceleration, jerk) are calculated against non-background frames. 

A critical step involves generating click-balanced sample weights to address extreme class and participant imbalance. Because a 2\,ms 'tap' action contains a fraction of the data compared to a 200\,ms 'hold' action, per-frame training weights are assigned inversely proportional to the duration of the click event and the total number of events produced by that user. This mechanism equalizes participant contributions and ensures short transient actions carry equal weight in the loss surface against sustained holds.

\subsection{Model-Specific Ingestion}
In the final stage, sequence arrays are reshaped explicitly for the respective model architectures.
For the Random Forest and Gradient Boosted Trees, sliding-window feature extraction converts temporal frames into heavily flattened tabular vectors. The window (e.g., 33 frames) processes local context to produce up to 69 composite static features per frame (such as range, zero-crossing rate, TKEO max, or kurtosis). 

In contrast, the FCN approach skips tabular extraction. Raw sequence tensors are ingested as batches. Labels are dynamically converted into a 3-channel heatmap reflecting target classes, mapping Make/Break onsets to probabilistic Gaussian bumps. When configured for localized sequence training, arrays are padded with an 8-frame gap silence delimiter, which prevents the sliding sequence generator from crossing temporal boundaries.


\section{Click-Intent Sequence Modeling}
\label{sec:modeling}
To understand user intent, the system models the data as a supervised time-series segmentation problem, mapped down to a per-frame classification task. The core feature engineering relies heavily on extracting analytical "distant context probes" that provide models with past and future temporal context, combined with instantaneous features like analog speed, digital signals, and distance to dynamic thresholds.

The primary algorithm used for inference is a Random Forest (RF) classifier. More advanced architectures, such as Gradient Boosted Trees (GBT) accommodating custom loss functions, and Fully Dilated Convolutional Networks (FDCN) for direct raw sequence temporal modeling, operate within the same structural framework.

\section{Parameter Optimization}
Once intent boundaries are parameterized, the system tests potential hardware settings without physically altering the peripheral. The engine simulates the analog mouse click Finite State Machine (FSM) frame-by-frame, testing its actuation behavior both with and without Rapid Trigger logic enabled.

The optimizer relies on the Covariance Matrix Adaptation Evolution Strategy (CMA-ES) to explore the parameter space. Candidates are evaluated through a multi-objective hand-crafted loss function that balances Recall (not missing clicks), Precision (avoiding accidental misclicks), and Latency (an early prediction penalty aimed at minimizing the temporal distance between simulated triggers and true user intent).
